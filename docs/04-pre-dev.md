## A. 验证类（先花小钱，避免花大钱）

### A1 ⭐ Provider API 尽调（红线测试的前置）
> 市场海外优先，但 **provider 仍按原方案走 Kling / Seedance（火山）现有渠道**——已验证配方在此，接入路径已知。国际版 API 作为备选项留观，不作为尽调主线。

| 项 | 要弄清的问题 |
|---|---|
| 接入 | Kling / Seedance（火山）API 开通条件、企业认证要求、审批周期 |
| 价格 | 每秒/每条渲染单价、并发限流、峰值配额——**直接决定成本模型（C4）** |
| 条款 | 商用授权、生成内容版权归属、二次分发限制（**影响社区发布合法性**） |
| 能力面 | API 暴露哪些控制（首尾帧/参考图/运动控制/多镜），与网页版差集——**决定 adapter 能编译什么** |
| 审核 | provider 侧内容审核规则与拒绝率——影响失败分类设计 |

**产出**：两页对比备忘 + 测试账号 + 预算获批。
**风险预警**：若 API 能力面显著小于网页版（常见），红线测试范围与 v1 承诺都要按 API 面收缩——这是最可能修正方案的一个点。

### A2 ⭐ 交付性红线测试（E3，方案 02/03 已定义）
- 设计探针集：每控制轴 × 每档强度 × 每模型 ≥3 次渲染（估 200-400 条，按 A1 单价做预算封顶）。
- 评分规约先写死（honored / partial / ignored 的判定标准 + 双人背靠背评分），避免"感觉还行"式结论。
- **产出**：CapabilityMatrix v0 + 词汇表白名单 v0 + 每轴证据记录。
- **这是整个准备期最重要的一项**：它决定 Recipe schema 敢做多细、UI 敢亮多少轴、landing 敢承诺什么。

### A3.0 建立访谈对象池（A3 的前置；同时是 D3 种子社区的起点）
- **打法：不冷招募，"进部落 + 用作品钓"。** 以创作者身份进入目标场域，发 3-5 条「拉片式调度解析」（成片 + 逐 beat 拆解）——这是未来 demo+配方卡的内容形态预演，来互动的人自动分层：问"怎么做到的" = 需求侧；讨论调度细节 = 供给侧候选。
- 渠道优先级（国际线；创始人不使用国内平台）：**Banodoco Discord**（AI 视频硬核创作者密度最高的社区）＞ **X/Twitter AI 视频圈**（Kling/Veo/Runway demo 的主流通地，breakdown thread 文化成熟）＞ **AI 电影赛事获奖名单**（Project Odyssey、Runway GEN:48、Kling 全球赛——供给侧密度最高）＞ Reddit（r/aivideo 等）＞ YouTube AI filmmaking 频道观众 ＞ Instagram Reels/TikTok（成片分发为主）。
- 目标池 40-60 人 → 筛供给侧 10-15、需求侧 20-25。付费访谈正当（长尾 100-200 元/30min；导演型用"提前体验 + 首发曝光"替代）。
- 一句话筛选器："你最近一条 AI 视频，为了拿到想要的效果渲了几次？"——次数多且能说清原因的是供给侧；"随缘抽卡"的是需求侧。
- 跟踪表：来源 / 类型 / 联系状态 / 意向等级。**此名单直接滚入 D3 种子导演群。**

### A3 种子用户验证（与 A2 并行）
- **供给侧**：10-20 位导演型创作者深访——愿不愿把调度结构化发布？署名/被 fork 对他们是否构成动机？现在手艺沉淀在哪（备忘录/飞书/私群）？
- **需求侧**：20-30 位内容创作者（vertical drama / faceless channel / MV·narrative 短片方向；ReelShort 式竖屏短剧在欧美正爆发，"短剧楔子"在海外同样成立）——"fork 一个镜头改成自己的"这个心智模型 5 分钟内能不能建立？拿纸面 FTUE（demo+配方卡示意图）做走查。
- **产出**：① 用户语言对照表初稿（内部概念→用户词汇，反哺 B1）；② 种子导演意向名单（≥10 人愿供稿即通过）；③ 定价感受区间。
- **止损线**：若供给侧普遍拒绝结构化发布（嫌麻烦/怕被抄），产品前提动摇，回炉定位——**这就是要在写代码前问的原因**。

## B. 产品定义类

### B1 ⭐ Recipe Schema v0 冻结
- 输入：A2 的词汇白名单 + A3 的用户语言表。
- 冻结范围：四层结构字段、Beat 定义、受控枚举、`advanced?` 边界、JSON Patch 格式。
- 同时冻结**用户语言对照表**（界面永不出现 schema/patch/adapter 字样；对外叫"镜头卡/导演卡"）。
- 版本策略：预发布期 schema version 0、不承诺兼容（借 dsh 的 pre-release 立场），但**事件日志信封**（type/seq/time/data）从第一天定死。

### B2 种子内容生产管线
- 定选题矩阵：情绪/景别/模型 × 50-100 个配方的分布（覆盖 FTUE 需要的"一眼想 fork"的类型）。
- 生产 SOP：内部方法论（skill）出配方 → 渲染 → 选 take → 双语标题/描述；**每条成本核算**（渲染费 × take 数）。
- 质量门：什么样的配方够格进首发库（兑现度全绿？被内测用户 fork 意愿？）。
- **产出**：管线文档 + 首批 10 条试产（试产同时是 A2 的补充数据）。

### B3 核心 UX 攻坚：Beat 编辑器
- 已识别的头号 UX 风险：**beats 是普通用户唯一必填的表演字段，beat 编辑器的易用性 = 产品的易用性**。
- 准备期做到：低保真原型（3 版方向：时间轴拖点 / 卡片列表 / 对话式生成）+ 5 人可用性走查，选定方向。
- 不做高保真、不写代码。

### B4 设计系统与品牌
- 设计 token 重建（Figtree + Zone 灰阶方案已有共识，实施时恢复）；landing 设计稿定稿。
- 品牌关账：Anselse 域名可注册性、商标初查、中文名（要不要？A3 顺带问）。

## C. 技术准备类

### C1 ⭐ 工程脚手架（B1 冻结后启动）
- pnpm monorepo 骨架（8 包布局按 03-tech §6）+ TS strict + ESM 统一配置。
- CI 三件套：lint/typecheck、编译快照测试框架（先空跑）、dependency-cruiser 单向依赖规则。
- `packages/recipe` 先行：schema + patch/diff + `resolveRecipe` 纯函数——**这是全系统的地基包，值得最先写、测最厚**。

### C2 事件日志与数据层定案
- 事件信封 + v1 事件清单（03-tech §2.2）评审定稿；Postgres 表结构（append-only 约束、`(project_id, seq)` 唯一）+ 读模型投影约定。
- 明确"哪些查询走投影表、哪些现场折叠"，避免开发中随手加表。

### C3 基础设施开户与安全基线
- **免费档位优先**：**web → Vercel**（静态 SPA + CDN）；Supabase（Postgres + Auth，免费档）+ Cloudflare R2（视频，10GB 免费 + 出口流量免费）+ Fly/Railway 免费档跑 API/worker + Sentry 免费档。目标：**内测期月固定成本 ≈ 0，钱全花在渲染上**。
- 队列可用 **pg-boss**（跑在 Supabase Postgres 上）替代 Redis+BullMQ，省一个付费组件；量起来再迁。
- 密钥管理约定：provider key 只在 server/worker 环境变量，前端零接触；`.env` 规范 + 泄漏检查 hook。
- 备份策略：Postgres 每日快照（事件日志是唯一真相源，**它丢了产品就没了**）。

### C4 成本模型（Unit Economics 草稿）
- 单条渲染成本（A1 数据）× 平均 take 数 → 每"成片"成本 → 订阅额度怎么定不亏。
- 免费层设计的止血线：FTUE 首渲免费到什么程度、防刷（同 IP/设备限额）。
- **产出**：一张可调参数的测算表。若测算表明免费 FTUE 补贴不可承受，FTUE 流程要改（如 fork 免费、渲染要额度）——宁可现在知道。

## D. 合规与运营类（国内上线的硬门槛，尽早并行）

### D1 合规路径（**后置，非当下重点**）
> 定案：合规不阻塞准备期与早期开发，公开上线前再关账。此处仅存档要点备查：
> AI 生成内容标识（EU AI Act/C2PA）· GDPR/CCPA（人脸参考图）· DMCA · **肖像权政策**（本产品最尖锐的一点，上线前必须有"真人授权声明 + 基础检测"）· 支付 Stripe · 协议模板。
> 唯一现在要留意的：渲染管线设计时给"内容标识/水印"留一个可插入的位置，避免将来返工。

### D2 配方权属与许可（产品级决策，不是法务细节）
- **必须在社区功能开发前定**：发布的 Recipe 默认许可是什么？fork 的权利边界？商用许可谁授予？
- 建议方向：类 GitHub——发布即接受平台默认许可（允许站内 fork + 署名），商用另行授权（为付费配方留口子）。写成一页决策文档。

### D3 种子社区运营准备
- 种子导演群（来自 A3 名单）的运营节奏设计：内测邀请制、首发配方的曝光承诺。
- 内容冷启动日历：首发库 50-100 条的题材节奏（对齐短剧热点周期）。

## F. 风险登记（准备期盯这五条）

| 风险 | 信号 | 预案 |
|---|---|---|
| API 能力面 < 网页版 | A1 尽调发现关键控制不开放 | 收缩 v1 承诺轴；评估"网页版半自动"过渡方案的合规性与成本 |
| 交付性不达标 | A2 中多数轴 ignored | 词汇表砍到极小可用集；产品叙事从"控制"退到"配方复用" |

| 肖像权滥用（参考图） | 名人脸/未授权真人照进入渲染 | 内测期邀请制天然可控；公开上线前（D1 关账时）上"授权声明 + 基础检测" |
