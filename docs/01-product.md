# Anselse · 产品背景与定位

> Direction 的 GitHub —— 导演优先的 AI 视频工具 + 可 remix 的调度配方社区

---

## 1. 一句话定位

**Anselse 是一个以「结构化 Direction Recipe」为原子单元的 AI 视频导演工具与 remix 社区：导演在这里沉淀调度手艺，长尾创作者在这里 fork 别人的配方出片。模型是可替换的水管，Recipe 是流通与增值的资产。**

对外一句话：**"别抽卡了。Fork 一个导演的镜头，改成你的。"**

---

## 2. 市场判断（为什么是现在、为什么是这个位置）

### 2.1 三层市场，只有一层能站

| 层 | 现状 | 结论 |
|---|---|---|
| 模型层（Sora/Veo/Kling/Seedance…） | 快速商品化、质量收敛、资本密集 | ❌ 不碰。骑在它的进步曲线上，不与它对打 |
| **编排/工作流层** | 把"裸模型"变成"可靠创作结果"的战场，远未解决 | ✅ **主场** |
| 分发/社区层 | 消费级赢家所在，需要流量底牌 | ⚙️ 不做纯分发，但把社区机制内化为产品结构 |

### 2.2 编排层未被解决的伤口（按与本产品的相关度排序）

1. **可导演性**：想要的运动/机位/表演拿不到，prompt 是轮盘赌。今天的"控制"是模型厂商附赠的零散功能，没有一个产品把「导演意图」本身当作一等公民的资产。
2. **手艺不可沉淀、不可流通**：一个人摸索出的调度经验（哪个模型怎么写才能出哪种表演）锁在个人备忘录里，无法复用、无法交易、无法累积成社区资产。Prompt 画廊（如 Midjourney 社区）只流通**文本**，一截图就被抄走，零沉淀。
3. 一致性 / 可编辑性 / 迭代成本：真实存在，但不是本产品第一刀（见 §5 边界）。

### 2.3 竞争格局与结构性缝隙

- **Runway / Pika / 可灵 / 即梦**：模型优先且**封闭**——它们做"给自家模型加控制功能"，商业上不可能做 model-agnostic 的配方流通层（会把用户导流出自家模型）。**这是它们结构上不愿进入的缝。**
- **ComfyUI / 节点工作流**：面向 workflow 而非 film，学习成本劝退绝大多数创作者；且节点图流通的是"管线"不是"导演意图"。
- **Prompt 社区 / 素材站**：流通单元是可被复制粘贴带走的文本/成片，无切换成本、无 remix 谱系。

**Anselse 的物种差异**：不是"控制更强的生成器"（会被巨头功能追平），而是"**导演意图在这里沉淀、流通、增值的地方**"——一个两边市场，不是一个功能。

## 3. 用户与两边市场

| 角色 | 是谁 | 来做什么 | 付出/得到 |
|---|---|---|---|
| **Director（供给侧）** | 硬核导演型创作者、短片人、AI 视频 prompt 高手（含创始团队自己） | 用结构化调度做出高质量镜头，发布 demo + recipe | 得到声誉、被 fork 数、（后期）配方收益分成 |
| **Remixer（需求侧）** | 不会/不想从零导演的长尾创作者：短剧作者、自媒体、MV/宣传片需求者 | 看 demo → fork recipe → 改主体/台词/风格 → 出自己的片 | 跳过学习曲线，直接站在导演的肩膀上出片 |

**关键机制**：Remixer 不需要学会走位/机位/beat 时序——他们消费 Director 做好的结构。这把纯导演工具"目标用户太窄"的死穴，转化为漏斗：**hardcore 供给 × 长尾消费，平台居中收网。**

FTUE（首次体验）即体现此结构：新用户落地页不是空白输入框，而是 **demo 视频 + 它的原始 Recipe**——点开即看到"这个镜头是被怎样导出来的"，一键 fork 改成自己的。

## 4. 差异化与护城河：三个复利回路

优势不是现在拥有的，是**设计出来让它随使用累积**的：

1. **切换成本回路**：用户在 Anselse 沉淀的 Recipe 库、角色/风格锚点、fork 谱系——离开即归零。Recipe 是结构化数据，只有在本工具内 fork/重放/remix 才有意义；**抄一张截图带不走**（对比 prompt 文本社区的致命伤）。
2. **分发回路**：每个发布的 demo 自带"fork 我"入口；被 remix 的作品在谱系上归功原作者——内容本身成为获客渠道，创作者有动机对外分享。
3. **数据回路**：平台独占地累积「哪种调度指令 × 哪个模型 × 什么场景 = 什么兑现率」的数据（每次渲染都是一次标注）。这份**交付性数据**反哺 capability 声明与自动编译质量，是任何巨头都没有的训练信号。

**创始团队的不公平优势（founder-market fit）**：导演手艺与 taste 本身，且已系统化为内部方法论资产（表演行动逻辑、镜头设计、逐模型 prompt 规则、带置信度分级的证据积累——以内部 skill 形式沉淀）。它的角色是**上游知识与内容工厂，不是产品部件**：为词汇表和编译规则提供候选条目（经交付性测试验证后以产品自有形式收录），并支撑冷启动前 50-100 个精品 Recipe 的批量生产。产品 schema 与词汇表由用户行为和交付性数据裁决，**不与任何单一方法论强绑定**——社区里其他导演的手艺同样要能流入。竞品难以复制的是这套经成片验证的知识积累与生产能力，而非某个具体文档。

## 5. 诚实的风险清单与产品边界

| 风险 | 应对（写进产品结构，不是口头承诺） |
|---|---|
| **模型交付性**（头号死因）：调度再精确，只值模型能听懂的部分；华丽的导演界面 + 40% 指令被无视 = 挫败机器 | ① Adapter 显式声明「能兑现哪些控制轴」，**UI 只亮可兑现的轴**；② 上线前跑「交付性红线测试」框定 v1 敢承诺的词汇范围；③ 社区以真实 demo 校准预期——用户看到的是"别人真做出来了"，不是空白框幻想 |
| **冷启动供给**：社区空手起 = 死 | 先工具后社区：创始团队作为首批 Director 产出 50-100 个精品 Recipe，有值得 fork 的存量后再开放社区机制；同步建立 10-30 人的种子导演关系 |
| **"prompt"稀释"recipe"**：若流通单元退化为可复制文本，三个回路全部失效 | 产品层面强制：发布单元 = 视频 + **结构化 Recipe**（可 fork 不可导出为等价文本）；prompt 只是 Recipe 编译后的中间产物，不是资产 |
| **巨头功能追平**：Runway 们必然持续加控制功能 | 不在"控制强度"上竞争，在"资产 + 谱系 + 社区"上竞争；控制轴可以被抄，fork 谱系和交付性数据抄不走 |
| **创作者忠诚度低**（追最强模型跑） | model-agnostic 结构：新模型出现 = Anselse 多一个 adapter，用户的 Recipe 资产在新模型上继续增值（换模型不换家） |

**v1 明确不做**（边界即定位）：
- ❌ 长片/多镜头时间线剪辑（单镜头 Recipe 打穿为先；装配是 v2）
- ❌ 跨镜头角色一致性引擎（仅提供"参考锚点"字段级支持，不承诺解决一致性）
- ❌ 自研模型 / 微调
- ❌ 通用文生视频（无 Recipe 的裸 prompt 模式不提供——那是别人的产品）
- ❌ 移动端

---

## 6. 商业模式（方向性，不展开）

- **近期**：渲染额度订阅（成本加成）+ Pro 功能（私有 Recipe、批量 take、高级轴）。
- **中期**：Recipe 市场抽成（付费配方 / 打赏 / 商用授权），Director 分成——把供给侧动机做实。
- **远期**：交付性数据 API / 面向工作室的团队版。

---

## 7. 命名

Anselse — 取自 Ansel Adams：以精确控制（Zone System）著称的摄影大师。寓意与产品同构：**用系统化的控制方法，取代对光的赌博。**
